## 1. 时间驱动引擎

### 1.1 时间结算触发
- 玩家在宫殿点击“睡觉”(直接跳至次日初始时刻（小时归零）)或者一天24小时耗尽后,调用advance_to_next_day()，触发一系列结算。

### 1.2 三层结算逻辑

#### 每日结算 (Daily Settlement)
- 遍历所有妃嫔 `concubine_list`：
  - 若 `pregnancy_days_remaining > 0`，将该值减 1。
  - 若减至 0，**触发生产事件中断**（详见 2.1），暂停正常时间流转。
- 遍历所有子女 `child_list`：
  - 若 `health > 0`（存活），`age_days += 1`。
  - 若 `age_days == 864`（48天/月 × 18年），将该子女加入皇帝宫殿的传位候选清单。
- 死亡角色不再推进年龄（`health = 0` 的子女跳过上述处理）。

#### 每月结算 (Monthly Settlement)
- 检查当前日 `day`，若 `day > 4`（每月4天）：
  - `day = 1`
  - `month += 1`
- 预留 `_process_monthly_events()` 空方法，用于未来扩展（如宫殿开销、随机事件）。

#### 每年结算 (Yearly Settlement)
- 检查当前月 `month`，若 `month > 12`：
  - `month = 1`
  - `year += 1`
  - 遍历仓库 `item_list`，每种物品 `quantity += 50`。

## 2. 生育系统

### 2.1 生产事件中断
当妃嫔孕期倒计时归零时：
1. **后台生成新生儿属性**（纯随机）：
   - 性别、健康值、聪慧值等完全由随机函数决定。
2. **强制显示命名弹窗**：
   - 游戏状态切换，要求玩家输入名字（不含姓氏）。
3. **数据封装与恢复**：
   - 生成全名：`family_name + 输入的名字`。
   - 创建 `Child` 实例，加入 `child_list` 和对应妃嫔的 `children` 列表。
   - 记录日志（如“第X年X月，某妃生下子女XX”）。
   - 恢复暂停的时间引擎，继续后续结算。

### 2.2 怀孕判定（侍寝触发）
- 仅在**侍寝**交互中触发，具体流程见 3.1。

## 3. 核心交互逻辑

### 3.1 侍寝 (Bedding)
- **前置条件**：当日剩余时间 ≥ 4 小时，目标妃嫔 `health > 0`。
- **消耗**：`GameState.hour += 4`
- **收益**：目标妃嫔 `favor += 固定值`，`experience += 1`。
- **怀孕判定**：
  - 若目标妃嫔未怀孕（`pregnancy_days_remaining == 0`）：
    - 生成随机浮点数 `r ∈ [0, 1)`。
    - 若 `r < 该妃嫔的 pregnancy_rate`，则：
      - `pregnancy_days_remaining = 36`
      - 追加怀孕日志。
- **日志**：追加侍寝记录（年份、月份）。

### 3.2 游玩 (Travel)
- **前置条件**：当日剩余时间 ≥ 4 小时，所有选中角色 `health > 0`。
- **消耗**：`GameState.hour += 4`
- **收益**：遍历玩家选中的妃嫔/子女列表，每人 `favor += 固定值`。
- **日志**：为每个参与者追加 `"第X年X月，同游[地点]"`。

### 3.3 赠送礼物 (Gifting)
- **前置条件**：目标角色 `health > 0`，所选物品 `quantity > 0`。
- **消耗**：物品 `quantity -= 1`（无时间消耗）。
- **收益**：目标角色 `favor += 物品的 favor_bonus`。
- **日志**：追加 `"第X年X月，获赠[物品名称]"`。

### 3.4 怀孕概率设定
- 选秀时，为每位秀女随机生成 `pregnancy_rate`，范围建议 `5% ~ 25%`。
- 该值在mvp版本前保持不变，后续可能考虑其他实现,但在mvp中不再动态调整。

## 4. 死亡与角色删除

### 4.1 删除机制
- 玩家在角色界面点击“删除”按钮。
- **逻辑**：
  - 目标角色 `health = 0`。
  - 从所在宫殿的 `moved_list` 中移除该角色，释放名额。
- **影响**：
  - 死亡角色保留在妃嫔/子女总名单中，但数值不再变化，不可交互。
  - 界面上名旁显示“（死）”字样（仅 UI 渲染，不改动底层 `name` 字段）。

### 4.2 业务逻辑全面拦截
- **时间引擎**：
  - 子女年龄增加：仅处理 `health > 0` 的对象。
  - 怀孕推进：若妃嫔 `health == 0`，其 `pregnancy_days_remaining` 直接重置为-1，防止死亡后触发生产。
- **交互限制**：
  - 侍寝、赠礼、游玩等所有互动，对象必须在 `health > 0` 时才能执行。
  - UI 按钮在检测到 `health == 0` 时应置灰或隐藏。
- **游玩名单过滤**：勾选参与者时，自动跳过 `health == 0` 的角色。

### 4.3 列表显示规则(妃嫔和子女)
- **排序**：渲染名单前进行排序，`health == 0` 的角色自动沉底,基于健康值和位分高低(把妃嫔的位分字符串映射成 rank_list 里的索引位置（Index）,子女只基于健康值就可以)。
- **隐藏已故筛选**：
  - UI 添加勾选框,若开启，则在生成显示列表时过滤：仅包含 `health > 0` 的角色。

## 5. 游戏流程控制

### 5.1 传位结局 (Abdicate)
- **功能**：触发传位结局，结束当前游戏。
- **校验**：
  - 目标子女必须存活（`health > 0`）且已成年（`age_days >= 864`，即满18岁）。
- **执行**：
  - 若条件满足，将 `state.current_state` 强制修改为 `"game_over"`。
- **返回**：包含操作结果的字典，供 UI 层读取。

### 5.2 重置游戏 (New Game)
- **功能**：初始化或完全重置游戏状态，不依赖旧的 `GameState`。
- **内部逻辑**：
  - 以工厂模式创建全新的 `GameState` 实例。
  - 硬编码初始值：`year = 1`，清空所有人物列表（`concubine_list = []`，`child_list = []` 等）。
  - 初始化默认数据结构：位分表 `rank_list`、宫殿配置（如储秀宫、重华宫及各妃嫔寝宫）。
- **调用时机**：
  - 玩家首次进入游戏。
  - 在传位结局画面点击“重新开始游玩”按钮。
- **内存管理**：UI 层用返回的新实例覆盖旧变量，旧后宫数据由 Python 垃圾回收自动销毁，实现彻底重置。
