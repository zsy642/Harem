### 🧩 各模块详解与依赖关系设计

为了绝对避免 Python 中常见的“循环导入（Circular Import）”报错，我们的依赖流向必须是**单向**的：
`main.py` -> `ui_manager.py` -> `logic.py` -> `models.py` -> `config.py`

#### 1. `config.py` (全局配置)

* **职责：** 存放所有不会随着游戏进度改变的静态常量。
* **包含内容：**
  * 窗口大小、颜色定义等（如 `WHITE = (255, 255, 255)`）。
  * 全局字典：`PICTURE_LIBRARY` (立绘路径映射) 。
  * 全局列表：`AVAILABLE_TRAVEL_PLACES` (游玩地点) 。
* **依赖：** 无。最底层文件。

#### 2. `models.py` (数据结构)

* **职责：** 只负责定义“数据长什么样”，**绝对不要在这个文件里写任何业务计算或 Pygame 渲染代码**。
* **包含内容：** 使用 `@dataclass` 定义的 `GameState`, `Concubine`, `Child`, `Item`, `Palace`, `Rank` 。
* **依赖：** 导入 Python 标准库 `dataclasses` 和 `typing`。

#### 3. `logic.py` (核心业务逻辑)

* **职责：** 游戏的“大脑控制器”。负责接收外部指令，修改 `models.py` 里的数据。**这个文件完全不知道 Pygame 的存在，它是纯 Python 逻辑。**
* **包含内容：**

  ##### ⏳ 时间与全局引擎


  * `advance_to_next_day(state: GameState) -> dict`
    推进天数，重置 `hour = 0`，执行每日/每月/每年的自动结算（孕期、年龄、物品发放等）。
    *触发时机：* 玩家点击“睡觉”，或任何消耗时间的操作结束后 UI 层自动检查 `state.hour >= 24`。
    *返回示例：* `{"success": True, "trigger_birth": True, "mother_id": "妃嫔A的ID"}`。若 `trigger_birth` 为 `True`，UI 应暂停并弹出命名对话框。
  * `trigger_birth(state: GameState, mother_id: Union[str, int], child_name: str) -> Child`
    生成纯随机的新生儿属性，正式加入子女列表。
    *参数：* `mother_id` 生母 ID，`child_name` 玩家输入的名字。
    *返回值：* 新创建的 `Child` 对象，供 UI 弹窗祝贺。

  ##### 💖 核心交互模块

  * `interact_bedding(state: GameState, concubine_id: Union[str, int]) -> dict`
    侍寝逻辑：扣除 4 小时，增加宠爱/经验，随机判定怀孕。对已故角色（`health=0`）拦截。
    *返回示例：* `{"success": True, "msg": "侍寝结束", "is_pregnant": True}` 或 `{"success": False, "msg": "时间不足，操作失败"}`。
  * `interact_travel(state: GameState, companion_ids: List[Union[str, int]], location: str) -> dict`
    游玩逻辑：扣除 4 小时，为选中的存活角色增加固定宠爱值，记录日志。
  * `interact_gift(state: GameState, target_id: Union[str, int], item_name: str, is_child: bool = False) -> dict`
    送礼逻辑：消耗仓库物品（不扣时间），增加目标好感度。`is_child` 用于区分子女/妃嫔。

  ##### ⚙️ 系统与管理模块

  * `delete_character(state: GameState, target_id: Union[str, int]) -> dict`
    将目标 `health` 设为 0（死亡），从对应宫殿的居住名单中移除它并释放名额。
  * `generate_draft_candidates(state: GameState) -> List[Concubine]`
    随机生成 3 名秀女存入 `state.draft_pool`，返回列表供 UI 渲染。
  * `accept_draft_candidate(state: GameState, candidate_id: Union[str, int], palace_name: str, rank_name: str) -> dict`
    将选中的秀女移入正式后宫，分配宫殿和初始位分。
  * `change_character_info(state: GameState, target_id: Union[str, int], new_picture_id: str = None, new_title: str = None, new_name: str = None, is_child: bool = False) -> bool`
    统一的数据修改接口，直接覆写立绘、封号、名字等。
  * `interact_abdicate(state: GameState, child_id: Union[str, int]) -> dict`
    传位逻辑：检查目标子女是否存活且年龄 ≥ 864 天，满足则将 `state.current_state = "game_over"`，返回成功信息。
  * `init_new_game(family_name: str) -> GameState`
    工厂函数，创建并返回一个全新的 `GameState`（无需旧 `state`）。用于“重新开始”功能，旧状态由 Python GC 自动回收。
  * **输入输出规范：** 所有会修改游戏状态的函数均需接收 `GameState` 对象，函数内部直接修改其属性。输出统一为字典（含 `success` 和 `msg`）或特定对象，方便 UI 层根据返回值做反馈。
* **依赖：** 导入 `models.py`。

#### 4. `ui_manager.py` (界面渲染与交互)

* **职责：** 游戏的“画笔”和“眼睛”。负责把 `GameState` 里的数据画到屏幕上，并捕获玩家的鼠标点击，然后调用 `logic.py` 里的函数。
* **包含内容：**
  * 状态机管理：根据 `GameState.current_state` ，决定调用哪个渲染函数（例如 `draw_main_interface()`, `draw_palace_interface()`）。
  * UI 过滤与排序：在绘制妃嫔名单前，执行“健康与位分排序”和“隐藏已故”的列表过滤逻辑 。
  * 事件分发：检测玩家点击了哪个按钮（比如“睡觉”、“传位”），然后调用对应的 `logic` 函数。
* **依赖：** 导入 `pygame`，导入 `models.py`，导入 `logic.py`。

#### 5. `main.py` (主程序入口)

* **职责：** 启动游戏。
* **包含内容：**
  * 初始化 `pygame.init()`。
  * 实例化全局唯一的 `game_state = GameState(...)`。
  * 开启标准的 Pygame `while running:` 主循环。
  * 在主循环中，统一调用 `ui_manager` 处理事件和刷新屏幕。
* **依赖：** 导入以上所有模块。
